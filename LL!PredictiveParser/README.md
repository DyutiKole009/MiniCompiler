# Non-Recursive Table-Driven Predictive Parser (LL(1))

A C implementation of a non-recursive, table-driven predictive parser. It uses an explicit stack and a manually encoded LL(1) parsing table to check whether an input string belongs to the language generated by the transformed grammar.

## Grammar

Original grammar:

```text
E -> E + T | T
T -> T F | F
F -> F * | a | b
```

After eliminating left recursion:

```text
E  -> T E'
E' -> + T E' | epsilon
T  -> F T'
T' -> F T' | epsilon
F  -> a F' | b F'
F' -> * F' | epsilon
```

The parser uses `e`, `t`, and `f` in the C implementation to represent `E'`, `T'`, and `F'`, respectively.

```bash
make
```

Or compile directly:

```bash
gcc -Wall -Wextra -std=c11 -o parser main.c
```

## Run

```bash
./parser
```

Enter a string ending in `$`, for example:

```text
a+b*$
```

The program displays each parsing step, including the stack, remaining input, and action taken. It then reports whether the input was successfully parsed or rejected.

## Parsing-table implementation

The parsing table is encoded in the `getProduction()` function. Each non-terminal/input-terminal pair selects a production number. `applyProduction()` pushes the selected production's right-hand side onto the stack in reverse order so that the leftmost grammar symbol is processed next.

The parser uses:
- `E`, `T`, `F` for non-terminals.
- `e`, `t`, `f` as internal representations of `E'`, `T'`, `F'`.
- `a`, `b`, `+`, `*`, `$` as terminals.
- `$` as the input end marker and bottom-of-stack marker.

## Example inputs

Valid examples:

```text
a$
b$
a+b$
a*b$
ab$
a**+b$
ab+a*b$
```

Invalid examples:

```text
$
+a$
a+$
a++b$
a**
```

Run an example by copying its contents into the program when prompted.

## Scope and limitations

- This is a syntax recognizer for the grammar above, not a general-purpose parser generator.
- The LL(1) parsing table is manually encoded; FIRST and FOLLOW sets are not computed dynamically by the program.
- The parser accepts only the terminals `a`, `b`, `+`, and `*`, followed by `$`.
- The grammar has no parentheses or whitespace handling in the input token stream.
